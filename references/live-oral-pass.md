# 现场口吻与内容幽默的专项改写

用户指出“书面、不像台上说话、罗永浩元素少”，或本场已选择更明显的口语幽默时，走此专项。plain只表示不需要额外Hook，不表示可以使用说明书语体。罗永浩方向也不能只在开场加一句段子：普通机制解释、例子、转场和回扣的语言都要适合本场讲者直接说出。

## 按现场情境改完整段落

先问这一段讲者面对谁、在解释哪个具体困难，听众能看到什么，下一句为什么值得听。技术定义仍保留，展开成“一个东西怎样发生变化、系统哪一步遇到问题、使用者下一步会怎样做”；去掉把教学目标、审稿字段或概念分类直接当台词的写法。

重点借鉴罗永浩的四种动作：
- 把看似正常的事摆在听众面前，认真追究一个具体细节，让原来被忽略的代价显出来。
- 用真实任务中的角色对话或当场设想推进解释，人物与场景为教学假设时保持清楚，不捏造讲者自己的经历。
- 对共同学习/工作习惯、工具局限作温和自嘲或观察；转向笑点后及时接回知识，不拿学生能力、出身或身份做靶子。
- 前面出现的物件、动作或结果在后面得到新含义，让笑点与主线有连续性。不要每次都重新编一个不相关比喻。

笑点可以是一句认真话里的小转折，也可以是一段逐步放大的情境；短金句只是其中一种。不要把“有铺垫、有解释”理解成每个笑点都必须在后一句把笑话解释一遍。没有笑声也能自然继续。

用户明确要更突出时，逐单元检查可用位置，不能仅说“适量”就把所有可能性删掉；也不用每节/每页硬塞一个笑话。普通知识段可以只有自然口吻，严肃操作说明照常克制。幽默强弱以实际段落的收益和用户反馈判断，不用笑话数或问号数过关。

## 用候选与独立读者校准

针对代表性的普通解释、生活案例和转场，比较当前段与现场口吻版；都给出相邻上下文，并保留同一事实与能力边界。反馈分别记录：哪句书面、哪处动作可见、哪句反差有知识收益、哪里说得像口号或硬凑笑点。按editor_workflow的select选择，不因新版更长或更夸张就判更好。

完成后连读全场：是否到处用同一个“你以为”句式，是否概念解释被笑话挤掉，是否一讲边界就切回论文语体，幽默是否让听众有距离感。主Agent保留最终判断，有授权与能力时用新上下文审代表段；无法独立审查时如实记录，不能把同一模型自评称为真人效果。

## Word中的角色区分

可念正文用独立段落样式LectureSpoken；默认微软雅黑13.5磅。备课提示、页间映射、PPT说明、来源及教学框架用较小的仿宋（建议11磅）；现场动作另设LectureNotes/Stage样式，绝不因夹在口播中就变成口播字体。标题仍用自己的层级。

用 `scripts/spoken_roles.py` 的ParagraphRoles识别“第一部分→翻页提示→口播→映射”的范围；只要纯口播时使用scope=spoken。段落样式加上实际run字体，不依赖主题默认。用户选择其他字体时保留角色差异；font文件存在与内部family名称应核实，未找到时选真实可用的中文等效字体。

导出后回读：每一条口播正文是否确实属于LectureSpoken，所有不朗读提示是否为说明样式；口播与说明的字体及字号应有可见差别。字体标签、颜色或小标题不能代替实际字体差异。程序和OOXML检查验证分配与属性；除非实际看过渲染或用户打开结果，不宣称已测得显示效果。

字体属性验收运行 `python3 scripts/verify_spoken_docx.py 教参.docx --expected 口播段落清单.json`。清单只放实际可念段落，舞台提示排除。用户选其他字体/字号时传对应参数；不能用默认值验收另一套样式。
