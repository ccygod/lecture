# 一次改稿，怎样知道评审和页码还对得上

页面增加了一页，讲稿里的“看第2页”可能已经指错。口播改了一句，旧评审里“类比边界已交代”的判断也可能失效。Lecture把这两类交接分别处理。

## 先体验稳定页码引用

本例的[页面索引](page-index.json)与[原始引用稿](slide-refs.raw.md)对应[排期案例](spoken-to-slide.md)。在仓库根目录运行：

```bash
python3 scripts/compile_slide_refs.py examples/slide-refs.raw.md examples/page-index.json --out /tmp/lecture-slide-refs.md
```

结果会将 `{{slide:schedule-conflict}}` 编为“页面1”，将 `{{slide:schedule-ready}}` 编为“页面2”。原稿的2026和180保持原值。若在索引开头插入封面，再编译时，两处引用将成为“页面2”和“页面3”。未知或重复ID会报错。

稳定ID表示页面身份，数组顺序表示最后页序。编译后还要看对应页面是否承担原来那项认知动作；脚本不会理解页内容。不要只给旧稿里所有数字全局加一。

## 再看版本绑定的评审怎样工作

下面描述仓库已有检查流程，不伪造一份“独立专家好评”。本发布示例由编辑者自审，未运行一套真实讲稿生成的前置确认与完整评审。

| 材料 | 要回答的问题 | 变化后的处理 |
| --- | --- | --- |
| 原文与交付契约 | 哪条是讲者主张，哪条是事实？落在实际稿件哪里？ | 保留主张，记录修正与理由，重核口播和上屏引用。 |
| 连续口播候选与评审 | 同一主张，两种讲法各保留了什么、损失了什么？ | 原候选变动后重新读相邻段落，提交当前文本的反馈。 |
| 情境审查包 | 案例有没有走完？类比关系与回扣是否成立？ | 从当前口播重新抽取引用及上下文，重审受影响位置。 |
| 最终口播与覆盖回执 | 实际采用的段落是否进入正文？ | 合稿后重新检查，不能用候选文件里出现过代替采用。 |

实际接口可先看帮助：

```bash
python3 scripts/editor_workflow.py --help
python3 scripts/scene_review.py --help
python3 scripts/check_delivery_contract.py --help
```

情境评审以 `packet_sha256` 绑定实际审查包；交付契约记录原文与稿件指纹；候选选择核对真实候选文本及计划。反馈过期时需要重新审查受影响的语义，不能只刷新指纹让旧回执重新“通过”。

## 脚本之后，还要读什么

原文引用存在，不代表改写保留了原意；获选句子出现在正文，不代表它放在了合适位置；回扣顺序正确，不代表回扣增加了理解。编辑者仍要读实际段落、邻接上下文与页面。没有独立评审就标注自审，没有试讲就说明只做文本审查。
